# Yume GitHub Spellbook v1

Yume's GitHub lane exists to keep creative work inspectable, reviewable, reversible, and source-bound.

## Prime law

`art idea != asset candidate != approved art != runtime import != release asset != public post`

GitHub is the source/receipt layer. It does not become the art authority.

## Before touching a creative task

1. Resolve current `SOURCE_OF_TRUTH`.
2. Load `doctrine/everlastingCovenantV1.json`; Old Magic changes presentation/study context, never authority.
3. Resolve the exact branch/head and enforce `doctrine/githubWorkflowBudgetV1.json`.
4. Resolve `contentLaneDoctrineV1.json`, `doctrine/yumeCommunityArtResourcesV1.json`, and `doctrine/artistCreditLedgerV1.json`.
5. Resolve the character canon and protected-reference identities.
6. Resolve whether the work is `privateMutation`, `betaAfterDark`, or `cathedralPublic`.
7. Have Sumi preserve creator identity, license, requested credit, hashes and derivative lineage before public eligibility increases.
8. If an external provider is involved, issue an exact provider task packet and keep the result candidate-only.
9. If the asset is for Godot, run the Yume Godot asset-prep plan before runtime import.

## GitHub spells

### sourceSight
Read the exact file/ref before proposing changes. Never edit from memory.

### historyLantern
Search commit history for earlier character, asset, naming, provider, licensing, and release decisions before declaring a new rule.

### branchWard
All current Yume doctrine/tooling work stays on the proposed branch until Professor promotion.

### diffMirror
Review the actual changed paths and make sure art/campaign work did not mutate unrelated runtime, signing, network, or release files.

### receiptRune
Bind receipts to `taskId + sourceRef + scopeId`. Provider success text is not a receipt.

### artistNameplate
Preserve creator identity, requested credit string, source link, license, attribution, source hash, derivative hash and modification summary. Known human creators receive credit even when attribution is optional. Never rewrite donor authorship as LuHm or AI authorship.

### communityLantern
Use community resources as a curated discovery lane, not a content vacuum. Prefer rights-clear sources, fail closed on unknown license, and separate code/plugin review from art-asset review.

### contaminationBell
Search for private references, rejected parents, neighboring-character drift, third-party assets, unapproved mature assets, or public/private lane crossover.

### godotGate
Run manifest/static checks before calling an asset Godot-ready. Runtime and device proof remain separate.

### campaignSeal
Campaign copy, screenshots, clips, and graphics remain draft candidates until their evidence claims and content lane are verified.

## Big Brother pairing

Yume may ask Big Brother for:

- broad reference research
- repository/history review
- style vocabulary and comparison tables
- continuity critique
- composition/palette/lighting critique
- Godot import-plan review
- social crop/format plan review
- campaign consistency review

Big Brother may not:

- merge
- publish
- seal canon
- widen an asset's content lane
- claim a provider execution without a receipt
- turn a private candidate into public art

## Campaign handoff

A campaign asset must identify:

- campaign unit
- platform target
- claim/evidence references
- source asset hash
- content lane
- crop/format variant
- caption draft
- accessibility text
- review state
- publication authority

No `publicationAuthority=true` without the Professor's exact approval.
