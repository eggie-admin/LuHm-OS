# LuHm-OS Machine Harness: Canon hardware-first starter

**Scope:** source candidate. One branded source-driven local cockpit, but no firmware, disk, network, GPG, APK or SQL mutation. Project Premonition is the current product name and Project Hydra remains the historical project alias.

## Identity and board gates

The spoken "Pico Pi Zero W 3" is **not an identified board**. Read the board silkscreen and attached ribbon controller. The Raspberry Pi Pico W/Pico 2 W are microcontrollers, not Linux SBCs; they can be sensor/USB firmware accessories but cannot host this Python/Flask container. Raspberry Pi Zero W and Zero 2 W run Linux, but have 512 MB RAM and a single data micro-USB OTG port. Raspberry Pi 3 Model B is a better multi-USB host, with separate DSI and CSI. Zero 2 W's 22-pin CSI ribbon is a camera port, **not a DSI LCD display port**. Display-driver compatibility is unverified. A slimline SATA drive requires a verified USB bridge, safe power budget and device selection; it is not native SATA on these boards.

## Sanest physical order

1. Photograph or read the exact board marking, ribbon connector/controller part, and slimline drive interface without exposing serials/IMEIs.
2. Start a supported Raspberry Pi OS Lite image for the verified SBC. Use microSD boot and a headless non-root user; use vendor firmware defaults and SSH keys under owner control.
3. Prefer **USB** for first reliable cable transport. Official Raspberry Pi OS Trixie supports `rpi-usb-gadget` on supported Zero boards; operator enables it via Raspberry Pi Imager. It reserves the data OTG port for gadget mode, so **do not simultaneously attach a USB storage host device**. On a Pi 3 B, use its USB host ports for phone tethering and storage as individually proven. Bluetooth is a backup for command/control, not a guaranteed USB-equivalent throughput link.
4. Samsung and Pixel remain signed stock Android clients by default. Use CameraX/Android sensors and authorized app permissions for mocap. Google GKI/vendormodules and Samsung Knox/AVB stay model-specific. No universal BIOS, IPS, ROM patch, bootloader unlock or fastboot flash.
5. **GParted:** operator-only offline host disk partitioning. **GRUB:** only on hosts that actually boot GRUB, not a universal Raspberry Pi boot chain. **Netplan:** only where chosen distro uses it, never silently edit a live network. **GPG:** owner's trusted device, existing `tools/ownerGpgBootstrap.sh` after identity proof; no new key generated by this harness.
6. Run source-only hardware profile and local container smoke. Move to USB/BT device tests only with hands-on owner proof.

## One branded build/run shell

Python/Flask is the smallest initial **optional** headless status surface. npm and Gradle remain offline/off-device build lanes, not resident background daemons on the Pi. Bootstrap is optional for later locally staged CSS; this first image uses original embedded CSS, no CDN. The Dockerfile uses Flask 3.1.2 and an unpinned multiarchitecture Python base tag **for development only**; pin the base image by reviewed digest, resolve image scanning and verify ARM64 device build before declaring deployable/production GREEN.

```sh
python3 -m unittest -v tests.testMachineHarnessSeal
python3 tools/machineHarnessSeal.py --source-ref "$(git rev-parse HEAD)"
export LUHM_SOURCE_REF="$(git rev-parse HEAD)"
docker compose -f machine-harness/compose.yaml build
docker compose -f machine-harness/compose.yaml up
# On the same Linux host only: http://127.0.0.1:8765/
```

Compose publishes exclusively to the **host loopback interface**, drops all Linux capabilities, runs non-root with a read-only filesystem, provides no /dev mounts and no remote SQL/provider tools. It is a local status app, **not** reachable automatically over Samsung USB tether or the public internet. A future authenticated transport gate can be added after USB interface/host role has been verified and a login/session design is approved.
