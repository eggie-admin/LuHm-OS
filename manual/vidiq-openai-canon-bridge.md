## One sane long-form production loop

1. Confirm the selected channel identity and read current source truth before a new content task. Read-only requests can inspect owned uploads and metrics; no unnecessary repeated polling.
2. Choose one artistic/technical story with source evidence: Godot demo, Canon character design, Blender/FFmpeg workflow, Samsung cockpit, or Rebel production. Claims about an installed working game or shipped APK require independent device/build evidence.
3. Keep editable original art, camera footage, voice, licenses and private references in owner-controlled storage. GitHub keeps reviewed manifests, hashes and source/receipt pointers only.
4. Pick the current content lane. Only specifically cleared `cathedralPublic` assets qualify for general YouTube publication; private `privateMutation` and invite-only `betaAfterDark` sources never leak into public exports.
5. Draft the script, shot list, thumbnails and video outline in ChatGPT. Render/edit locally where practical with VLC, FFmpeg, Blender and Godot; no paid provider is activated by this document.
6. Research keywords, titles, packaging and audience using vidIQ **only when their credit cost and task budget are accepted**. Distinguish measured YouTube performance from estimates, generated recommendations and zero-data cold-start assumptions.
7. Review exact channel, target video, title, description, tags, final thumbnail, image rights, credits, subtitles and category. **Do not change YouTube metadata, schedule, publish, reply, clone voices, buy generation or cross-post without the Professor's approval of exact final values.**
8. After an expressly authorized provider action, inspect the actual YouTube result and record a redacted, exact-source receipt. An in-chat draft, GitHub PR or mock screenshot is not proof of publication.
9. If a video exists later, use its owned metrics, viewer feedback and retention to improve the next video; never reinterpret absent metrics as success.
