# LuHm OS · Drive-to-GitHub Asset Alignment

**Authority:** Professor. **Scope:** storage and production routing for Hydra, Rebel, Yume and Pets. **Status:** canonical routing contract only. This document is not an APK install, Blender render, signing approval, Drive permission change, asset rights clearance or public release.

## One source, one file server, one preview lane

- **GitHub `eggie-admin/LuHm-OS`:** canonical source, manifests, sanitized logical asset keys, CI jobs, SHA-256 receipts, version references. A successful branch build is source/build proof only.
- **Google Drive owner-controlled private vault:** original images, donor archives, Blender masters, original audio/video, working GLBs, hashes and durable finished binaries. A Drive search listing **never** authorizes or executes media.
- **GitHub Codespaces Ubuntu 26.04:** Python 3, headless Blender, GIMP 3, FFmpeg. This is the remote production garage. It starts only when a Codespace instance actually runs.
- **Godot 4:** 3D model/rig/proof and plugin preview, not the video finishing engine.
- **ChatGPT LuHm cockpit:** artistic direction and task/receipt controls; installing Samsung APK never installs a ChatGPT plugin automatically.
- **Samsung:** cockpit and end-device review after a signed, tested APK exists.

## Current source-of-truth precedence

Current user/Professor decisions → current exact GitHub source and canon → current live Drive permission/asset proof → versioned source/asset receipts → old archives. **Do not let an older 'FINAL MASTER' label replace a current reviewed artifact.**

The original shared Rebel collection was observed with anyone-writer access, as was the legacy public-write collection. The legacy collection labeled private control was observed as anyone-reader. Keep all three **untrusted for protected media and credentials**. The separate owner-only Rebel private-production area is the preferred working vault. These are point-in-time observations; review current permissions before moving media. Do not embed original private Drive IDs or filenames in public doctrine.

## First real Rebel render

1. Select **one** original/private or rights-cleared character or scene asset. For loose GLB/bar models, verify source ownership, license, mesh import and hash, do not assume public usability.
2. Create a shot/version manifest; keep screenplay and donor assets out of GitHub. Existing `media/pirate-daddy-film/episode-template.json` supplies the **seven shots / five sections** render grammar.
3. Headless Blender makes the source candidate; GIMP 3 handles stills/textures. Godot 4 verifies geometry and character animation independently when needed.
4. Use `host/ai-ffmpeg/ai-ffmpeg.py` to encode a **private** review MP4, preserving task ID and file hashes. Do not mark a card title animation or generated proof as an actual Rebel final.
5. Professor reviews the exact MP4. Copy the approved working master to the restricted Drive archive; record a **sanitized logical pointer + digest** in GitHub.
6. Public post, music rights, APK/F-Droid distribution, Render deployment and chat plugin install each remain their own decision.

## Continuity and duplication rules

- Do **not** bulk-import Google Drive into Git, duplicate the contents of an archive by default, or mass-rename/move 3D files.
- A duplicated title or similarly named folder does not prove identical bytes. Use **SHA-256** before deduplication.
- Legacy snapshot/document branches are evidence and rollback, not live source authority.
- Previously accepted jQuery source uses `doctrine/jqueryPluginContinuityV1.json` fast reuse with targeted changed-code checks.
- Run only task-relevant media checks. Never create an extra database, deployment service, automatic background agent or paid GPU just for file alignment.
